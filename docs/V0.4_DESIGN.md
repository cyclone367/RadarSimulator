# RadarSimulator v0.4 设计 · 数据录制与回放

状态：待评审。基线为 v0.3.0 Preview，提交 `f62784860120340931b2585fb9f56b9c79c4b2d7`。

## 需求和功能范围

- 实时模式支持开始录制、停止录制并保存文件。记录目标、航迹、检测集合、扫描参数和时间。
- 回放模式支持打开本地文件、播放、暂停与继续、停止、单步、1x／2x／4x 和时间轴定位。
- 回放以已保存的完整帧驱动 PPI、航迹表、详情及状态。用户可以选中航迹并查看对应帧中的数据。
- 本版本范围为本地单文件录制和回放。格式转换、网络回放、录制编辑与压缩留待后续。

## 当前架构

| 模块 | 基线行为 |
| --- | --- |
| `RadarSimulation` | 持有 `RadarTarget` 和 `RadarTrack`。目标按固定 0.1 秒步长更新，检测由波束与范围判定。由检测点更新估计速度、预测位置及有界历史，航迹超时以墙钟时间判断。 |
| `RadarServer` | 持有仿真模型、每客户端的 CRLF 接收缓冲和 100 ms 扫描定时器。每周期更新目标与扫描角、检测和航迹，发送现有 TCP 通知，最后更新航迹超时状态。当前 `trackUpdated` 在处理单个检测时发出。 |
| `RadarWidget` | 直接从服务端读取角度、范围、检测 ID 和航迹。50 ms 定时器请求重绘，控件负责绘制与鼠标选中。 |
| `MainWindow` | 直接读取服务端状态和航迹，100 ms 刷新状态、列表及详情。实时按钮和参数控件操作服务端，航迹选中在表格与 PPI 间同步。 |
| `main.cpp` | 在主线程启动监听 9000 端口的服务并创建窗口。 |

`RadarTarget` 是仿真真值，`RadarDetection` 是扫描命中事件，`RadarTrack` 是由检测形成的航迹。当前 PPI 和表格依赖航迹及本周期检测集合，因此回放需要保存三者中可显示的状态。单独保存真值会缺失历史和预测，单独保存检测事件则需要重新运行跟踪逻辑。

## 新增模块

| 模块 | 接口与边界 |
| --- | --- |
| `RadarFrame` | 值类型快照，复用目标和航迹结构。一个帧包含 PPI、表格和详情共同读取的数据。 |
| `RadarServer::snapshot()` | 主线程按值生成快照。增加独立的帧提交信号，在每次 100 ms 仿真步完整提交后发送，保留现有 `trackUpdated` 的语义和 TCP 处理路径。 |
| `RecordingWriter` | 接收完整帧，后台依序编码和写入。负责头、完成标记、临时文件、最终保存和错误通知。 |
| `RecordingReader` | 验证头和每帧，构建稀疏索引，按偏移读取或按时间查找。返回值帧及明确的格式、IO、截断错误。 |
| `PlaybackController` | 管理回放状态机、倍速、定位、读请求和虚拟时间。输出已保存的帧。 |
| `MainWindow` / `RadarWidget` | 窗口在实时和回放间选择展示帧，同一帧用于全部视图。控件接收快照并处理绘制与选中，文件和播放时钟由独立模块管理。现有选中航迹的 1–3 秒预测线可继续由保存的估计速度、角速度和范围做确定性绘图投影。详情仍显示已保存的预测值和更新时间。 |

### 采样频率与时间基准

- 默认每 100 ms 采样一次，约 10 FPS。启动即采初始帧。扫描中以服务端每次仿真步完成为默认采样触发点，在检测和航迹超时更新之后取同一时刻的完整快照。扫描停止期间由录制调度器按同一间隔采样，恢复扫描后交回仿真步触发。两路互斥，切换时按最近采样时间去重。UI 重绘、单目标检测信号和 360° 整圈都不触发采样。
- 调度按单调时钟记录真实采集时间。事件循环延迟时保留实际时间间隔，禁止补造中间状态或一口气重复采样。停止请求先关闭常规采样，再尝试入队最终快照。配置在会话开始时固定，v0.4 默认 100 ms，后续可开放配置。较慢频率可跳过仿真步，快于 100 ms 的采样本身无法提高当前模型的更新频率。
- 使用 QElapsedTimer 等单调时钟，记录以首帧为零的整数微秒 `elapsed_us`。时钟读数与上一帧落在同一微秒时，取上一帧加一，确保严格递增。结束时长取停止时间与末帧时间的较大值。UTC 只用于文件来源和展示模型内的航迹时间。
- 基线每步按固定 0.1 s 更新。在 10°/s 下每步转 1°，一圈约 36 s。100 ms 与仿真步对齐可保留每个正常提交的角度变化，包括 359° 到 0°。例如初始方位 45°、距离 1000 m、角速度 0.5°/s、径向速度 20 m/s 的目标，一步后为 45.05°、1002 m。回放按已存帧呈现，保留原始步进，PPI 的 50 ms 刷新不会产生额外运动细节。若事件循环延迟，帧间隔可能超过 100 ms，回放保留延迟和已提交的状态。


回放切换的是本地展示源。TCP 仍由 `RadarServer` 控制既有实时会话，照常接受请求及发送原有通知。回放帧独立于实时模型，`PlaybackController` 不调用仿真推进、检测或航迹超时。回放时禁用窗口中的实时扫描参数和录制按钮，明确提示 TCP 仍连接实时服务。退出回放立即显示最新实时快照。

## 数据结构和文件格式

| 候选 | 优点 | 代价 |
| --- | --- | --- |
| JSON Lines | 逐行读写、便于排查和恢复，天然表示变长目标、航迹和历史数组 | 文件较大，编码与解析有开销 |
| CSV | 方便表格工具检查扁平数据 | 嵌套历史需拆表或转义，难以保证一个时刻的所有实体一致 |
| 二进制 | 体积更小，固定结构便于高吞吐读取 | 需额外定义字节序、长度、版本兼容与诊断工具 |

v0.4 选 UTF-8 JSON Lines，建议扩展名 `.radar.jsonl`。每行一个 JSON 对象，首行是头，其后是完整帧，正常保存以结束行收尾。不保存增量或在文件内持久化索引。写入 LF，读取允许 LF 或 CRLF。

| 行类型 | v1 必填字段 |
| --- | --- |
| `header` | `type: "header"`、`format: "RadarSimulatorRecording"`、整数 `version: 1`、ISO 8601 UTC `created_at_utc`，含毫秒，以及正整数 `nominal_interval_ms`（本版默认 100） |
| `frame` | `type: "frame"`、从 0 连续递增的 `seq`、严格递增的整数 `elapsed_us`，第一帧为 0。另含 `scan`、`targets`、`tracks`、`detected_ids` |
| `end` | `type: "end"`、`frame_count`、`duration_us`，时长不小于最后一帧时间 |

- `scan` 保存 `running`、`scanning`、`angle_deg`、`direction`、`beam_width_deg`、`max_range_m`、`speed_deg_s`。方向枚举为 `clockwise` 或 `counterclockwise`，速度是非负幅值。基线正向方位角按北起顺时针递增，停止时保留配置方向。运行与扫描标志、范围和波束参数属于必要显示状态。选中航迹属于查看交互，按播放时当前选择显示。
- `targets[]` 保存 `id`、`angle_deg`、`distance_m`、`speed_m_s`、`angular_speed_deg_s`、`state`（`outside` 或 `detected`）。
- `tracks[]` 保存 `id`、`angle_deg`、`distance_m`、`estimated_speed_m_s`、`estimated_angular_speed_deg_s`、`predicted_distance_m`、`predicted_angle_deg`、`last_update_utc_ms`、`hit_count`、`state`（`tracking` 或 `lost`）、`history`。
- `history[]` 保存 `angle_deg`、`distance_m`、`timestamp_utc_ms`，保持模型中的顺序。`detected_ids` 保存当前检测集合。
- 距离、角度和速度以现有模型单位记录，使用可往返的双精度表示。读取验证必填字段、类型、有限数、枚举和 ID 唯一性，保留基线模型可产生的有符号距离和未归一化预测角。时间与序号须处于 JSON 可精确表示的整数范围。已知版本允许未知附加字段，未知版本给出明确错误。
- `elapsed_us` 是回放唯一时基，`seq` 用于校验帧连续性。UTC 时间跳变不影响回放。

以下为按基线扫描步进和目标参数编写的两帧示例。第一目标在该时间段尚未进入波束。

```jsonl
{"type":"header","format":"RadarSimulatorRecording","version":1,"created_at_utc":"2026-11-04T08:00:00.000Z","nominal_interval_ms":100}
{"type":"frame","seq":0,"elapsed_us":0,"scan":{"running":true,"scanning":true,"angle_deg":0,"direction":"clockwise","beam_width_deg":20,"max_range_m":5000,"speed_deg_s":10},"targets":[{"id":1,"angle_deg":45,"distance_m":1000,"speed_m_s":20,"angular_speed_deg_s":0.5,"state":"outside"}],"tracks":[],"detected_ids":[]}
{"type":"frame","seq":1,"elapsed_us":100000,"scan":{"running":true,"scanning":true,"angle_deg":1,"direction":"clockwise","beam_width_deg":20,"max_range_m":5000,"speed_deg_s":10},"targets":[{"id":1,"angle_deg":45.05,"distance_m":1002,"speed_m_s":20,"angular_speed_deg_s":0.5,"state":"outside"}],"tracks":[],"detected_ids":[]}
{"type":"end","frame_count":2,"duration_us":100000}
```


## UI 与回放语义

- **实时**：开始录制前选择保存路径。录制中显示状态、时长和停止按钮。结束后显示保存结果，失败时展示原因及可恢复文件路径。
- **加载**：后台校验和索引，可取消。加载失败保留当前展示。开始录制和进入回放互斥，切换前可选择保存正在录制的会话。
- **回放**：加载成功展示首帧并进入就绪态。播放按 1x、2x 或 4x 推进。暂停保持当前位置，继续以该位置建立新时钟锚点。停止回到首帧，播放到末尾保留末帧并暂停。退出回放回到实时模式。
- **单步与定位**：在就绪或暂停态，单步前进一条记录。拖动时间轴时暂停，提交定位后显示时间不大于游标的最后一帧；定位后保持暂停。显示已过时间和总时长。选中 ID 若不在当前帧则清空详情。
- **计时**：由单调时钟计算当前播放时间，定时器负责唤醒。卡顿时按目标时间选帧，避免累计漂移。切换倍速先保存当前虚拟时间，再重置锚点。

## 异步写入与停止

- 主线程只生成值快照并尝试入队，后台工作线程独占文件、编码和 I/O。使用有界 FIFO 和合并唤醒，禁止为每帧向 Qt 事件队列另投一个无界消息。状态和错误通过排队信号回传。
- 初始上限为 100 个待写快照且估算占用不超过 64 MiB，任一先达到即拒绝新帧。估算包含目标、航迹与历史数组，另计工作线程正在处理的一帧及编码缓冲。100 帧约等于默认频率下 10 秒积压，字节上限可能先触发。
- 首次溢出立即结束采样，后台尽量排空已接受帧，保留标为不完整的 `.part`。磁盘满、短写、刷新失败或关闭失败时停止写入并保留可读前缀，报告错误、文件路径和已写完整帧数。两类失败都不写成功结束标记、不覆盖目标文件、不静默丢帧后继续。
- 正常停止进入「正在保存」，冻结采样并排空 FIFO，验证写入计数后追加 `end`。检查每次写入，刷新用户态缓冲及系统文件缓冲，关闭文件，再在同目录原子重命名为最终文件，禁止覆盖。只有重命名成功才提示保存完成。退出程序时给出等待保存或保留未完成文件的选择。
- 写入同目录独占的 `.part`，初始每 1 秒刷新一次用户态缓冲。异常退出后磁盘上可能只剩前缀。断电时可恢复范围取决于系统与存储设备的持久化行为。

## 恢复、索引与定位

- 正常打开验证头、版本、连续序号、递增时间、字段类型、每行终止符及 `end` 的计数和时长。中间坏行、末尾残行、缺失结束行或结束行不一致时，报告首个异常位置，并提供只读恢复。未知版本或坏文件头拒绝加载。
- 恢复只呈现第一个异常前、以换行结束且通过验证的连续完整帧。即使坏行之后还有看似有效的记录，也不跨越断点拼接。至少一帧才可回放，恢复时长为最后有效帧时间，明确标记截断并保持原文件。
- 后台首次打开顺序校验并建索引。以首帧及每 100 帧保存 `elapsed_us`、`seq` 与 64 位行首字节偏移。定位对时间二分，跳转到不晚于游标的索引项，再向前读至下一索引项前，选择不晚于游标的最后一帧。常规定位只解析一个索引段，默认最多 100 帧。
- 播放顺序读取并有界预取，时间轴快速拖动只处理最新请求。使用会话和请求编号丢弃过期结果，读取线程不访问 UI 或实时模型。初始限制单行 8 MiB、索引占用 32 MiB，写入端同样拒绝超长帧，超过读取限制时给出明确错误。数组数量、单帧占用和索引间隔结合性能结果复核。

## 开发顺序

1. 引入快照和周期末采样点，先把实时视图接到统一帧上，跑现有协议与服务端测试。
2. 实现 JSON Lines 编解码、流式写入、读取和索引，完成格式、故障和恢复测试。
3. 实现带可注入时钟的回放控制器，覆盖倍速、单步、定位和状态迁移。
4. 接入 Widgets 控件，完成录制、播放与退出回放的交互和 TCP 并行回归。
5. 用长录制测量性能，确定容量限制并完成 Windows 操作验收。

## 验收标准

- 可录制完整会话并重新打开，播放同一帧时扫描、检测、航迹预测和历史与录制一致。
- 播放、暂停、继续、停止、单步、三个倍速和前后定位均满足上述行为。
- 回放不会改变实时目标或向 TCP 广播回放数据。旧有 CTest 与新增关键模块测试全部通过。
- 不兼容、损坏及异常退出文件均有可理解的错误或恢复结果。长文件读取不会把全部帧装入内存。
- UI 能清楚区分实时、录制、回放和恢复状态，并在退出回放后即时恢复实时展示。

## 风险与待确认

- 完整快照的磁盘开销随目标数、航迹数及历史长度增长。队列与索引上限为初始值，性能阈值和适用数据规模需通过实测确定。
- TCP 在回放期间继续操作实时服务，用户可能误以为 TCP 会控制回放。需在 UI 明示，并在集成测试覆盖并行操作。
- v1 保留模型原始 UTC 时间、有效的有符号距离和未归一化预测角。模型后续若调整单位或状态语义，须明确升级文件版本或提供迁移。
- 主线程调度抖动可能造成采样间隔拉长。写入故障或断电也可能丢失尾部数据。结构校验无法识别所有仍合法的静默损坏。
- 待确认默认保存目录，以及是否在未来版本增加录制文件校验或压缩。
